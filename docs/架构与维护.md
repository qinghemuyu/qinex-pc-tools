# 架构与维护

## QInEX-Link

```text
Windows Raw Input / 键鼠 Hook ─┐
                              ├→ capture → sender → link → UART → P4 Mode C
可选 kmboxNET 本机 UDP 输入 ──┘
```

| 文件 | 责任 |
| --- | --- |
| `src/capture.cpp` | 捕获线程、按键与位移缓存、独占与应急释放、Pointer 快捷键协作 |
| `src/sender.cpp` | 发送节拍、时间窗聚合与直通、心跳、停止时全抬 |
| `src/protocol.h` | F6/F7/F8 与 PING 的纯函数字节编码，供生产与测试共用 |
| `src/link.cpp` | 串口枚举、连接、波特率与能力协商、状态解析、重连 |
| `src/netserver.cpp` | kmboxNET 输入服务与 monitor 回读，输入仍通过串口交付 |
| `src/performance.cpp` | Windows 进程和线程调度保护 |
| `src/taskbar_widget.cpp` | 可选任务栏状态与操作入口 |
| `src/settings.cpp` | EXE 同目录的 `link.json` 和自启动设置 |

客户端根据当前连接的 Mode C 与板端激活状态决定是否转发。这里读取的是设备状态，不生成激活凭据。维护时保留独占释放、断线清理及紧急键；不能只让界面看似停止而保留按下状态。

## QInEX Pointer

```text
UDP → 有界接收队列 → JSON 状态归并 → 校准/裁剪/旋转/显示几何 → 指针
Media Foundation / DirectShow → 最新帧邮箱 → D3D11 / DXGI 合成呈现
```

核心在 `pointer_core.*`，处理 JSON、状态归并、坐标变换与仿射拟合。`udp_receiver.*` 搬运数据并按来源过滤，`capture_output.*` 与 `directshow_capture.*` 管采集，`capture_presenter.*` 负责视频与指针合成。

`main.cpp`、`app_ui.cpp`、`calibration.cpp` 和 `desktop_helpers.cpp` 负责界面、生命周期、校准与桌面协作。`settings.h` 与 `profile_store.h` 保存用户设置和设备档案，保留 Unicode 路径与原子写入。

Android 工具由 `QINEX_WITH_ANDROID_TOOLS` 控制，关闭时不编译其服务与界面，不准备内嵌依赖；开启时使用原有的 ADB 服务、备份恢复与覆盖包流程。桌面显示与 Android 手机图标分别保存状态。

## 统一桌面入口

`qinex-pointer/src/pointer_runtime.h` 暴露初始化、消息预处理、设置/菜单入口和退出接口。`pointer_desktop` 静态库由 Link 和独立 Pointer 共用；`standalone.cpp` 只负责独立运行时的进程身份与消息循环。

Link 在首次点击「光标设置」或需要恢复已保存连接时初始化模块。光标设置仍使用原有类名，但以 `WS_CHILD` 嵌入 Link 主窗口；顶部按钮只切换内容，不创建第二个设置顶层窗口或托盘。Link 主线程负责统一消息循环和退出，子窗口销毁不发送 `WM_QUIT`。两个部分共用 `glass_theme.h` 的绘制函数和配色。宿主按工作区与 DPI 缩放，子页随宿主布局并保留未应用草稿；GDI+ 必须在所有光标对象销毁后关闭。

Link 快捷键发现优先本进程 Pointer，输出窗口必须与选中的 Pointer 主窗口同属一个进程；未初始化内置光标时仍可回退到独立版。串口捕获、发送、UDP 接收及采集后台线程的协议和职责不变。

## 修改边界

- 协议字段变更同步文档和固定样例；保持未知扩展字段、能力回退与超时语义。
- 两个程序的窗口类名、消息名、热键 ID 和窗口属性构成兼容接口；更名需同时维护两端。
- 采集回调与输入回调避免引入阻塞操作；日志、存储和界面工作保持在适合的线程。
- 指针接收时间、PC 呈现时间与手机输入时间不是同一个时钟。实际性能结论附设备、固件、配置和测量范围。
