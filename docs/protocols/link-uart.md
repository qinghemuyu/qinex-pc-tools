# Link 串口协议

本文对应 `qinex-link/src/protocol.h`、`sender.cpp` 与 `link.cpp` 的当前实现。使用场景是 PC → P4 Mode C 的原始键鼠输入；字节向量由 `link_protocol` 测试验证。

## 连接与能力协商

- 初始串口为 921600、8N1，无硬件流控。收到 `STATUS: Mode C ... act=1 ...` 后，当前连接才具备转发条件。状态文本通常以换行结束。
- PC 发送 `KMV2\n`；收到含 `OK` 的 KMV2 回执后改用 F8 鼠标帧。等待约 350ms 未确认时保留 F6。重连后重新协商。
- 可选 3Mbps 提速发送 `KMLINK 3000000\n`，收到 OK 后切波特率；PC 继续用空鼠标帧保活，并要求在新波特率读到有效状态。验证失败退回 921600。默认不启用提速。
- 转发前检查当前连接状态、Mode C 与当前板的 `act`；界面会话解锁缓存不能替代这些实时条件。

## 二进制帧

多字节整数为小端。坐标增量为鼠标原始 counts，不是屏幕坐标；按钮位图低位依次是左、右、中及侧键。校验为前面所有字节的 XOR，不包括校验字节自身。

| 帧 | 长度 | 顺序 |
| --- | --- | --- |
| F6 鼠标 | 8 字节 | `F6 buttons dx:int16 dy:int16 wheel:int8 xor` |
| F8 带时间鼠标 | 9 字节 | `F8 buttons dx:int16 dy:int16 wheel:int8 gap_125us:uint8 xor` |
| F7 键盘 | 10 字节 | `F7 modifiers keys[6] reserved=0 xor` |
| FE PING | 9 字节 | `FE timestamp:uint64`，无 XOR 尾 |

`dx/dy` 饱和到 -32768…32767，滚轮饱和到 -128…127。`keys[6]` 使用 HID Keyboard Usage，空位为 0；修饰键沿用 HID 的 Ctrl、Shift、Alt、GUI 左右位顺序。普通键最多六个。

F8 的 `gap_125us=0` 表示重新锚定时间线；1…255 表示 125µs…31.875ms。编码器对非零微秒值按 `(gapUs+62)/125` 取整并限制到 1…255。发送线程在首次输入、时间不递增或间隔超过 31.875ms 时传入 0。协议时间片不是 PC 调度或手机显示的实测保证。

示例：左键按下，`dx=1, dy=-2, wheel=-1`：

```text
F6 01 01 00 FE FF FF 08
F8 01 01 00 FE FF FF 01 07   # 间隔 125µs
```

键盘示例为左 Shift + A/B（modifier=2，键码 04/05）：

```text
F7 02 04 05 00 00 00 00 00 F4
```

## 心跳、释放和故障

发送线程有约 100ms 的空鼠标保活与约 1s 的 PING。PONG 回显原时间戳，PC 用自身时钟算往返；该值不是单向或手机触摸延迟。

停止转发、断开前与退出时走 `sender::releaseAll()`：清除本机捕获状态，并在链路可写时发送鼠标按钮全零及键盘全零。链路已经断开时无法承诺设备收到释放；重新连接与应急退出仍须清本机独占状态。`Ctrl+Alt+Q` 为应急释放键。

串口写入可能只完成部分字节，`link.cpp` 会处理补写并统计未完成情况。测试注入失败时应验证控制状态和释放，不能仅检查 UI 文案。

## 状态与诊断

PC 识别 `STATUS: Mode ...`、PONG、KMV2/KMLINK 等行。常用字段含 `act`、`usb`、`fps`、`dps`、`ukm`、`gmax`、`dmax`、`uq/uqmax/udrop`、`uerr`。缺失字段按解析器的未知值或兼容默认值处理，不可视为已支持能力。

`fps/dps` 原始值是板端统计窗口的增量，UI 才换算速率；最大耗时不是分位数。协议扩展应忽略不认识的可选字段，并保留旧固件的 F6 回退。
