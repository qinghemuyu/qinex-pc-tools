# 构建指南

## 桌面功能

需要 Windows x64、Visual Studio 2022 C++ 桌面工作负载（MSVC v143、Windows SDK）与 CMake 3.21+。默认功能不需要 Python、Java 或 Android SDK。

在仓库根目录执行：

```powershell
.\build.ps1 -Test
```

也可以使用 CMake：

```powershell
cmake -S . -B build/desktop -G "Visual Studio 17 2022" -A x64
cmake --build build/desktop --config Release --parallel 4 -- /p:TrackFileAccess=false /nr:false
ctest --test-dir build/desktop -C Release --output-on-failure
```

`QINEX_BUILD_LINK` 与 `QINEX_BUILD_POINTER` 分别控制两个工程，默认 ON。`QINEX_WITH_ANDROID_TOOLS` 默认 OFF。也可直接以 `qinex-link` 或 `qinex-pointer` 作为 CMake 源目录，源码仍应保留在完整仓库中，以包含公共许可文件。

PowerShell 入口默认使用 `build/all-desktop`；单项目分别使用 `build/link-desktop`、`build/pointer-desktop`。程序位于构建目录的对应项目 `Release/` 子目录。脚本不会停止已运行程序；遇到 EXE 锁定请先退出该程序。

## Android 手机工具完整版

额外需要 Python 3.9+、Android Build Tools 34.0.0、ADB 35.0.2-12147458 和锁定版本的 Temurin 17。官方来源及许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。

1. 通过 Android SDK Manager 安装 Build Tools 34.0.0；命令行可执行 `sdkmanager "build-tools;34.0.0"`，按 SDK 要求接受适用许可。
2. 从仓库根目录运行以下依赖准备命令。下载会校验 SHA-256；失败会停止。

```powershell
python qinex-pointer/tools/fetch_adb.py
python qinex-pointer/tools/fetch_temurin.py
```

3. 指定 SDK Build Tools 路径后构建，例如 SDK 安装在 `C:\Android`：

```powershell
.\build.ps1 -Project Pointer -AndroidTools -Test `
  -AdbDirectory "$PWD\dependencies\platform-tools" `
  -AndroidBuildTools "C:\Android\build-tools\34.0.0"
```

默认 JDK 位于 `qinex-pointer/build/android-dependencies/`；已有相同版本时可传 `-AndroidJdk`。直接调用 CMake 时，对应参数为 `QINEX_ADB_DIR`、`QINEX_ANDROID_BUILD_TOOLS`、`QINEX_ANDROID_JDK`。后两者及 ADB 不会从旧开发仓库自动查找。

版本清单在 `qinex-pointer/tools/android_runtime_versions.json`。构建阶段逐项读取版本、生成资源和摘要清单；用户运行程序时使用 EXE 内嵌依赖。更换版本必须同步清单并重新测试。Java 缓存版本不一致时使用新的构建目录。

完整版产物位于 `build/pointer-android/qinex-pointer/Release/`，显示六个页面。Android 测试使用隔离数据目录及模拟手机命令，默认不连接真实手机；真机 USB、无线 ADB、ROM 权限和图片覆盖需另行验收。

## 生成本地运行包

在根目录执行 `./package.ps1`，会先构建并测试，再生成 `dist/desktop/` 下的两个 ZIP。包内包含程序、说明、LICENSE、NOTICE 和适用的第三方声明；不包含个人设置、校准档、日志或模拟器。

该入口只生成默认桌面版。Android 完整版的公开二进制分发须另外完成对应依赖许可与源码提供核查。运行构建产物不会自动生成 Git 提交、标签或远程发布。
