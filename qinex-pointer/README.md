# QInEX Pointer

完整桌面模块同时内置于 `QInEX-Link.exe`，可从顶部「光标设置」切换到同一主窗口内的设置区；独立版继续保留。合并入口、统一退出和旧配置迁移见 [合并版使用](../docs/合并版使用.md)。

QInEX Pointer 是 Windows x64 独立光标程序，把 P4 或 S3 + QInEX 发来的指针画到电脑采集预览中。指针层透明、鼠标穿透且不抢焦点；手机通过采集卡输出画面时，可由电脑承担指针绘制。接入外部视频融合器时，程序也可单独输出纯色背景与光标，作为融合器的一路色键图层。

界面围绕「设备 → 画面 → 保存并使用」组织。日常在首页查看设备和预览状态、暂停或恢复显示，需要修正偏差时再进入校准。具体操作见 [使用说明](使用说明.md)，开发验收见 [测试与验收](../docs/测试与验收.md)。

桌面版左侧导航组织五个页面，启用 Android 工具的完整版增加第六个手机工具页面，底部固定显示保存和应用操作。普通模式采用官网黑绿配色、细网格和透明细边框分区，操作按钮采用荧光绿，二次元模式采用浅色玻璃并保留对应文案；侧栏可即时切换，保存后记住选择。设置区采用短过渡：切页 150ms、换肤 180ms、悬停 110ms，新输入可立即结束页面过渡。动效结束即释放临时资源；采集或全屏输出运行、窗口隐藏或失焦、远程会话及系统关闭动画时停用动效。合并版各页保持统一窗口尺寸。

## 当前功能

| 页面 | 主要操作 |
| --- | --- |
| 首页 | 查看设备、预览和实际显示状态，连接、暂停、恢复，返回画面或外观设置 |
| 设备 | P4 / S3 接入、复制电脑地址、绑定已收到数据的设备、独立 15 秒演示、诊断详情 |
| 画面 | 外部画面覆盖、固定桌面区域、窗口跟随、采集卡全屏输出、纯色背景全屏（融合器）；完整手机画面与高级裁剪设置 |
| 校准 | 采集或融合全屏使用当前范围快捷键（默认 F8）拖拽校准；九点精调、单点重采、撤销、截图放大与独立验收 |
| 设置 | 8 种光标样式、自定义图片与热点、四组快捷键、显示延迟、断流隐藏、启动连接、场景导入导出 |

演示拥有独立接收器、临时端口、显示窗口和状态；真实设备继续接收，原画面与校准保持不变。演示自动结束，也可提前结束。它验证本机接收和绘制，不代表真实手机已经对齐。每页「本页帮助」在程序内显示当前步骤。

## 接入与成果保护

| 来源 | 输入、映射与光标发送方 | 接入方式 |
| --- | --- | --- |
| P4 单机模式 | P4 统一固件在板内映射并发送光标 | 将设备页展示的电脑局域网 IPv4 填到板端目标；固定 UDP 6533 |
| P4 上位机直驱模式 | QInEX-Link 转发键鼠到 P4，板内映射并发送光标 | 同上；键鼠转发和光标接收分别配置；自定义快捷键需 QInEX-Link v0.1.13+ |
| S3 + QInEX | QInEX PC 主程序映射并发送光标 | 同机目标与来源默认 `127.0.0.1`，默认 UDP 6533 |

P4 在板载页「网络 → VP 光标（PC / App）」启用 VP 光标，在「高级」中填入电脑 IP，并关闭「兼容旧版 App」和「自动发现接收端」。S3 发送端使用 JSON v2、固定目标并关闭自动发现。P4 填写的接收端 IP 是电脑地址，本程序的「P4 地址」是板子地址。地址未知时可留空接收，确认后点击「使用收到数据的这台设备」。一次未绑定接收会话只跟随首个有效发送 IP，超时不会自动换到另一台设备。

来源类型、来源 IPv4 和接收端口共同标识设备档案。A → B → A 时恢复各自完整画面和校准；未知来源从默认校准开始，未绑定来源不复用设备校准。身份依据是网络接收身份：同一板子换手机或改变板端触摸映射后，仍需重新检查。

配置分为编辑草稿、正在使用的设置和保存结果。连接与画面修改通过「应用本页」或继续操作提交；形状、有效大小和颜色即时预览。保存只持久化，不重启接收；实际改变连接来源才重建会话。界面重建保留草稿，未保存退出有提示。

`pointer.ini` 保存上次设置，`profiles/` 保存设备档案，均位于程序目录，使用 Unicode 路径和 UTF-16 配置。每个文件完整写入临时文件后原子替换；写失败保留该文件旧内容。场景 INI 可单独保存设备与画面组合，导入采用场景自身校准。截图、采样和撤销历史只在本次运行保留。快捷键是程序级偏好，切换设备或打开场景时不会跟着改变。

暂停只隐藏指针，接收继续更新；「断开设备」停止真实接收。托盘可恢复窗口、暂停 / 恢复或退出。设置页可分别录入暂停 / 恢复、显示 HUD、调整范围和返回设置四组快捷键；默认依次为 `Ctrl+Alt+F10`、`F7`、`F8`、`F11`。普通字符键需要搭配 Ctrl、Alt 或 Shift，返回设置不可关闭，`Esc` 和固定后台逃生键 `Ctrl+Alt+F12` 始终可从全屏返回设置。包含 `Ctrl+Alt+Q` 的组合始终保留为 QInEX-Link 紧急释放键；让 Link 识别当前自定义绑定需配套 QInEX-Link v0.1.13 或更高版本。可选启动时连接上次设备。

主窗口的关闭按钮（X / Alt+F4）隐藏到系统托盘，接收、光标和已启动的采集／融合输出继续运行，页面草稿保留。点击托盘图标可恢复窗口，右键菜单的「退出程序」才会结束进程；有未保存修改时仍提示保留窗口处理。首次隐藏会提示恢复方式，图标可能位于任务栏的隐藏图标区域。资源管理器重启后重新安装托盘图标；托盘不可用时保留可见窗口。程序、窗口和托盘图标已嵌入 EXE，运行包无需额外图片。

光标提供箭头、圆点、十字、圆环、涟漪、锁定框、轨迹和自定义图片八种样式，尺寸范围为 12～144 像素。选择图片后可在棋盘格预览中拖动热点，滚轮放大后微调。在热点编辑器点击「保存并应用」时，图片会立即转换为带透明通道的 `custom_cursor.png`，长边最多 512 像素，热点同时写入 `custom_cursor.ini`；这两个文件不等待主页「保存」。当前选中的光标样式、大小和颜色仍需点击主页「保存」，才会在下次启动时自动恢复。两种全屏输出和普通透明叠加层使用同一图片、缩放和热点；图片缺失或损坏时回退十字光标。

## 采集卡全屏输出

画面页选择「采集卡全屏输出」后，程序会读取所选设备实际报告的分辨率、精确帧率和像素格式。「自动低延迟」按设备能力选择；60、120、144、165、240 帧档只在设备真实提供时出现，也可以展开「精确规格」直接选择完整模式。精确模式保存稳定键，设备能力发生变化时会明确报错并要求重选，不会在后台悄悄降档。

少数专用驱动能被 Windows 识别和打开，却不通过 Source Reader 公开模式列表。程序会继续读取设备 Presentation Descriptor 和当前格式；仍无列表时显示「自动兼容（使用驱动当前格式）」并直接尝试出帧，启动后以实际回读的分辨率、帧率和格式为准。此兼容回退只用于 Auto，精确规格仍必须可枚举、可回读和完全匹配。

采集引擎默认先使用 Media Foundation。设备打不开、格式无法协商或打开后收不到首帧时，程序会释放该入口并自动切换到系统 DirectShow 兼容引擎；无需按品牌选择，也不会同时占用同一采集卡。设备列表合并两种 Windows 接口，DirectShow 独占设备也可被选择。画面页会显示当前采集方式；精确规格切换引擎后仍须匹配同一宽高、帧率、像素格式和扫描方式。

收到第一帧后程序才进入无边框全屏。视频与指针由同一个 D3D11 / DXGI Flip 输出表面合成，使用双缓冲和最新帧邮箱，不建立播放队列；指针数据和视频帧都会直接唤醒呈现线程，不再受 15 ms 界面定时器限制。默认「自动同步」避免撕裂；勾选「极限低延迟」后，在系统支持时立即 Present，代价是移动画面可能出现撕裂。双屏时默认推荐非主屏，保存时使用合并后的采集设备稳定身份和 Windows 显示目标设备路径恢复，不按列表序号猜测设备。

画面页用一行摘要显示当前规格、实测输入帧率和采集引擎，完整协商结果、丢帧数据与错误原因放在「采集诊断详情」。采集全屏 HUD 分行展示接收 FPS、画面变化估算、重复采样比例、新视频呈现 FPS、重绘 FPS、回调→Present 耗时、帧间隔 P95 / 峰值、连续相同画面时长、时间戳重复 / 倒退和入口跳过。累计帧数与最长连续相同时间可在「采集诊断详情」查看。软件耗时只覆盖采集帧进入本程序至成功 Present 的 PC 链路，不能当作 HDMI 输入、采集卡内部处理或显示器发光的端到端延迟。

接收 FPS 统计本程序实际取得的视频帧，重复画面也计数；画面变化与重复比例比较叠加光标前每帧固定 64×36 网格的 RGB 值，忽略 alpha，不扫描整张图。新视频呈现按首次 Present 的采集帧序号计数，重复画面的不同序号仍计入；重绘还包含同一视频帧上的光标 / HUD 更新。若持续移动视角时看到「接收 200、画面变化≈60、重复采样 70%」，说明已分析样本中只有约 60 次/秒的画面变化，可继续核对手机游戏帧率、HDMI 输出和采集卡实际规格。静止菜单、黑边和局部小变化可能让变化率偏低，压缩噪声可能让它偏高，不能直接宣称采集卡造假或得到手机游戏真实 FPS。

分析约每秒刷新。P95 表示该窗口内 95% 的交付间隔不超过此值，峰值帮助观察卡顿。时间戳只诊断样本流时序；即使每帧时间戳递增，画面仍可能重复。DirectShow 通过 `IMediaSample::GetTime` 检查时间戳是否存在，缺失时显示不可用。入口跳过仅指程序单槽邮箱被新帧覆盖，和驱动丢帧分开；中间帧未分析时不猜测其内容。重连、分辨率或原生格式变化会重建分析基线。检测不会据此丢帧或节流，保持原有最新帧输出策略。

播放器与指针共享同一套裁剪、旋转、镜像、拉伸和等比适配。基础模式保持视频比例，播放器生成的黑边不参与指针坐标；高级模式会自动读取实际输入分辨率，并把 `crop → 旋转 → 镜像` 同时用于画面和热点。分辨率改变后立即按实际帧尺寸重算，视频断流时隐藏指针并自动尝试重连。

全屏 HUD 默认显示，默认按 **F7** 隐藏或重新显示、按 **F8** 进入光标范围调整、按 **F11** 或 `Esc` 返回设置。范围调整中拖框内可平移，拖边缘或四角可缩放，`Enter` 应用，`Esc` 取消。这三组按键都可在设置页更改，HUD 会显示当前绑定。本机输入可用时也可右键打开菜单；菜单可切换 HUD、调整范围和退出，托盘保留进入、退出和停止采集入口。上位机直驱模式独占输入时，QInEX-Link v0.1.13+ 会读取 Pointer 当前绑定并直接交给对应操作。退出全屏会保留采集连接，便于再次进入；「停止采集」才会关闭视频采集。暂停指针、停止采集画面和断开指针设备互不影响。当前版本只输出视频，不会打开音频输入或更改 Windows 音频设备。

采集输出模式的精细校准直接冻结新的解码视频帧，并要求该帧在触点停稳后到达；它不会截取可能被其它窗口遮挡的桌面。无新帧时取样继续等待，不会使用断流前的旧画面。

## 纯色背景全屏（融合器）

该模式给外部视频融合器提供一路色键图层：QInEX Pointer 在指定输出显示器上全屏绘制纯色背景和光标，手机 HDMI 画面从融合器的另一路输入接入，最终的色键抠除与画面合成由融合器完成。程序不采集手机视频，也不打开或占用采集卡，因此可与采集卡录制、环出或其它采集软件同时使用。

画面页选择「纯色背景全屏（融合器）」后，选择输出显示器和背景色，再点击「启动融合输出」。背景提供绿幕、蓝幕、黑场和自定义颜色；应按融合器的色键设置选择，并避免与光标颜色相同或过于接近。保存后会恢复所选显示器、背景色和光标范围；已保存显示器不在线时不会改投其它屏幕。

全屏默认按 **F7** 隐藏或显示底部 HUD、按 **F8** 调整光标范围、按 **F11** 或 `Esc` 返回设置；三组按键可在设置页分别更改。范围调整时对照融合器最终合成画面，在框内拖动可平移，拖边缘或四角可缩放，`Enter` 应用，`Esc` 取消。本机鼠标可用时也可右键切换 HUD、调整范围或退出，托盘同样保留返回和退出入口。上位机直驱模式独占输入时，QInEX-Link v0.1.13+ 会读取并放行当前绑定。

融合全屏底部 HUD 默认显示 Present 速率 / 帧数、输出刷新率和指针数据状态，不显示采集 FPS、采集帧或采集延迟，避免把无采集链路的数据伪装成采集性能。HUD 会随 HDMI 进入融合器；正式色键合成需要干净背景时，使用当前 HUD 快捷键（默认 **F7**）隐藏。暂停指针时纯色背景和 HUD 继续输出；退出全屏只结束这一路显示，不影响指针设备接收，也不涉及采集卡启停。

## 画面对齐与校准

完整手机画面可见时，选择基础模式，框选边界贴合手机四边并排除黑边、工具栏。程序将完整手机坐标映射到所选矩形；检查四角、中心和移动方向后再保存。

采集卡和纯色融合模式优先使用快捷范围校准。启动全屏后触发当前范围快捷键（默认 **F8**），屏幕上会出现光标可达范围框；拖动框内可整体平移，拖动八个边角控制点可缩放。采集卡模式直接对照视频，融合模式对照融合器最终合成画面，让范围与手机触摸坐标实际应覆盖的区域一致，再按 `Enter` 应用。程序会立即换算为校准矩阵，不改变采集视频或纯色背景；按 `Esc` 可取消并保留原校准。应用后移动光标检查四角、中心和轨迹，满意后返回设置保存。

预览裁掉手机边缘，或需要把完整采集帧放入视频容器时，使用高级模式：分别描述帧尺寸、帧内手机区域、预览保留区域和旋转。两种模式明确区分框选对象，避免重复扣除黑边。

窗口跟随按客户区比例保存区域，随窗口移动和缩放更新。固定工具栏、侧栏或布局变化后需重新框选；关闭后需重新选择。窗口最小化时隐藏，可选仅预览在前台时显示。桌面使用 Per-Monitor DPI Awareness V2，支持负桌面坐标与多显示器。

快捷范围校准后仍存在局部偏差时，再进行九点精调。先绑定设备，在手机开启系统指针位置，使用普通跟随触摸路径：

1. 选择九宫格位置，设置 3～30 秒准备时间，默认 5 秒。
2. 主窗口最小化；采集卡模式自动恢复全屏，独立提示显示倒计时和等待原因。准备后最多等待 45 秒，收到明确的新鲜按下状态、位置稳定至少 800 ms 后自动截图；用户同时确认视频真实触点停稳。
3. 截图冻结后全屏画面自动退到后方。先在截图中标记真实触点，确认按钮才会启用；4× / 8× 放大镜与方向键支持原图 1 像素微调。QInEX-Link v0.1.13+ 会自动放行本机键鼠，旧版需使用 Link 收放键。
4. 九点齐全后计算并应用校准；可单点重采，清空和恢复默认可撤销，误差过大时指出优先重采的位置。
5. 计算后另采独立验收点，显示物理像素误差。该点不参与九点拟合，重新拟合后需重新采验收点。

取样可取消，条件不足继续等待，超时保留成果。采集卡取样期间使用当前退出快捷键（默认 F11）会取消本次取样并返回设置；其它预览模式可按 Esc 取消。

## JSON v2 接收语义

一个 UDP 数据报对应一个 UTF-8 JSON 对象：

```json
{"type":"move","nx":0.25,"ny":0.75,"show":true,"down":false}
```

| 字段或消息 | 行为 |
| --- | --- |
| `type` | 必填：`move`、`show`、`hide`、`heartbeat` |
| `nx` / `ny` | 0～1 的有限数值；首个完整坐标建立位置，之后缺失的轴沿用上值 |
| `move.show` | 省略时为 true；没有有效位置时保持隐藏 |
| `move.down` | 省略时沿用按下态；隐藏时清除按下态 |
| `show` / `hide` | 显示已有有效位置 / 隐藏并清除按下态 |
| `heartbeat` | 仅更新活跃时间，不恢复位置、显隐或按下态 |

`show/down` 必须为 JSON 布尔值。扩展字段允许存在，但须满足 JSON 语法；重复协议字段、未知类型、非法 UTF-8、越界数值和畸形对象会被拒绝。报文最大 4096 字节，没有必填 `version` 字段。来源过滤使用 IP，不绑定发送者的临时 UDP 源端口。

接收线程记录报文、来源和本机接收时刻，主线程顺序归并。接收队列最多 2048 条，显示延迟队列最多 4096 个完整状态。默认即时显示，可设 0～2000 ms 延迟；位置、显隐、按下态一起延后。默认断流 2000 ms 后隐藏并清除按下外观及延迟队列；超时值必须大于延迟加 500 ms。

配套 S3 上位机静止约 500 ms 后补发完整 `move`，接收器重启后可恢复静止位置、显隐和真实按下态。正常移动、点击仍即时发送；真实输入和测试轨迹分别保存，测试结束或取消恢复真实状态。

## 专业坐标模型

输入直接使用 JSON 归一化位置，不重新积分电脑鼠标位移。板端参考分辨率、灵敏度和指针偏移已体现在发送位置中；接收端处理手机触点到电脑预览的显示变换。

| 参数 | 坐标空间 |
| --- | --- |
| A：`calibration` | JSON 位置到手机可见触点的仿射校准，默认单位变换 |
| F：`content` | 手机内容在旋转前完整采集帧中的归一化矩形 |
| C：`crop` | 预览保留的完整采集帧归一化矩形，与 `content` 使用同一整帧基准 |
| O：旋转 / 镜像 | 裁剪后额外顺时针旋转，再按显示方向镜像 |
| D | 裁剪后整帧在桌面目标容器中的实际显示矩形 |

```text
JSON (nx, ny) → A → F → C → O → D → 物理像素指针热点
```

高级模式采用 `p_pc = D(O(C(F(A(p_json)))))`。设 `content=(cx,cy,cw,ch)`、`crop=(kx,ky,kw,kh)`：

```text
(x,y) = A(nx,ny)
(fx,fy) = (cx + x*cw, cy + y*ch)
(u,v) = ((fx-kx)/kw, (fy-ky)/kh)
旋转：0°=(u,v)，90°=(1-v,u)，180°=(1-u,1-v)，270°=(v,1-u)
镜像后位置为 (ox,oy)
PC 热点 = (D.x + ox*(D.w-1), D.y + oy*(D.h-1))
```

裁剪后帧尺寸为 `(frameWidth*kw, frameHeight*kh)`，90°/270° 时交换宽高，再等比居中适配到 `target`。拉伸时 D 等于目标容器。基础模式令 F/C 为完整区域并拉伸至已框选的完整手机矩形。全程保留浮点精度，绘制时取整；箭头尖端、圆点中心、十字交点为热点。超出手机内容或可见裁剪范围的位置隐藏。

双层黑边分别建模：`content` 描述帧内黑边，D 描述预览容器外部黑边。1920×1080 帧中央手机内容为 1920×864 时，`content=(0,0.1,1,0.8)`；整帧等比放进 1000×400 容器，手机内容约 711×320。预览已裁去帧内黑边时，`crop` 设为同一矩形，`content` 保持原值。

快捷范围校准把四个 JSON 边角逆解为用户框选的屏幕范围，并拟合 A，因此旋转和镜像下仍按视觉边界工作。九点校准会冻结 JSON、截图和完整几何，逆解 D/O/C/F 得到手机内容位置，与 JSON 组成拟合点对。九个训练点使用仿射最小二乘；退化采样、画面外预测或采样最大误差超过 10 px 时不应用。拟合残差与新增点验收分别显示，不能用同一批训练点证明独立精度。校准计算以当前实时采集几何为准；同一裁剪和画面比例下的分辨率变化视为等价，裁剪、旋转、镜像或有效比例实际改变时才要求重采。

## 使用边界与验收

P4 普通光标通常约每 16 ms 发送一次。协议没有发送时间戳或序号；UDP 丢包、乱序和采样间短促按下可能无法完整呈现。显示延迟按接收时刻人工调整，不能精确自动同步视频。宏、多触点、自动拖拽等独立触摸轨迹不能仅由普通光标报文代表。

目标是 PC 预览；录制或直播需确认画面包含桌面指针叠加层。更换手机、板端旋转 / 触摸校准 / 偏移或显示模式时，复核四边、中心、直线、对角线、圆周以及窗口缩放后的落点。

真实手机、P4/S3、采集卡触点对齐和输入独占联调，以及真实用户可用性验收仍需完成。

## Android 系统光标工具

启用 Android 工具的完整版，第六个「工具」页提供 USB / 无线 ADB、手写笔开启与原设置恢复，以及静态光标图片、热点和 dp 尺寸编辑。手机接入 P4 时可使用 Android 11+ 无线调试，配对地址与连接地址分别填写。Android 15+ 优先使用 ROM 允许的用户开关；ROM 关闭支持或未能确认时尝试强制属性，分别反馈用户开关与强制写入结果。开启成功只代表配置已读回，强制属性变更后重启，还需在手机确认实际悬停图标。

USB 连接需另外开启手机的「USB 调试」，用数据线直连电脑并解锁授权；Windows 的手机 ADB 接口驱动由厂商提供。刷新区分空列表、待授权和离线，诊断详情保留设备列表原文及本机服务信息。设备解析兼容短列表的制表符与 `devices -l` 的空格对齐；回归测试使用实际详细列表格式覆盖发现、授权和空列表提示。

默认悬停图标不可见时，可独立「开启触摸反馈」，直接写入当前 Android 用户的 `show_touches=1` 并读回；通常即时生效，用 P4 仅移动光标确认。页面显示开启、关闭、默认关闭或未知状态，提供关闭与恢复原反馈设置。首次修改前独立备份原值，重复操作、重新启动工具后仍保留最初备份；原来没有该设置时恢复为缺失状态。触摸反馈同时显示手指触摸点，关闭开发者总开关可能被系统重置。此操作需要授权 ADB；普通写入被拒绝时保留实际错误，已有 ROOT 可明确授权后重试。

图片覆盖先拉取手机的 `framework-res.apk`，识别十字或悬停圆点及其大图标 / 矢量分支，再解析覆盖集合和策略。用户必须确认实际悬停图标路径。公开覆盖可直接安装，系统覆盖通过 Magisk 模块安装；安装后检查覆盖状态和实际显示。默认空图标没有图片可替换，应用自带的图标也不由这些系统资源接管。

ADB、AAPT2、zipalign、apksigner 和精简 Temurin OpenJDK 17 内嵌到 EXE，按需释放并校验摘要。Android 偏好、恢复记录及签名独立保存到当前用户目录；编辑手机图片不会写 PC 的自定义光标文件。依赖清单与许可、恢复记录和诊断导出可从「诊断详情」打开。功能边界与验证见 [测试与验收](../docs/测试与验收.md)。

维护者首次构建需安装 Android Build Tools 34.0.0，并运行 `python tools/fetch_temurin.py` 下载锁定版本的 Temurin 17。CMake 使用 `ANDROID_HOME` 寻找 SDK，可通过 `QINEX_ANDROID_BUILD_TOOLS` 和 `QINEX_ANDROID_JDK` 指定依赖路径。`tools/android_runtime_versions.json` 锁定来源与版本；构建参数见 [构建指南](../docs/构建指南.md)，二进制再分发须保留相关许可并核对依赖义务。

离线验证：`ctest --test-dir ../build/pointer-android -C Release --output-on-failure` 覆盖命令引用、超时取消、缓存校验以及模拟手机的权限拒绝、部分写入恢复和重复开启。`../build/pointer-android/qinex-pointer/Release/pointer_android_tests.exe --package <android.jar> <验证目录>` 使用真实内嵌工具生成并验证签名包，验证目录与真实 Android 用户资料隔离。`../build/pointer-android/qinex-pointer/Release/pointer_android_tests.exe --adb-smoke` 检查本机 ADB 服务启动、只读设备发现和退出清理，不修改手机设置。实际 ROM 的 idmap、模块挂载和 P4 悬停显示需真机验收。
